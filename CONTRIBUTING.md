# Contributing

Thanks for helping grow the Claude Code Marketing Library. Two ways to add an entry.

## Option 1: open a pull request

1. Pick a category folder from the [directory](README.md#directory). If none fits, propose a new one in your PR description.
2. Add a file at `{category}/{slug}.md`. Use a short, descriptive, hyphenated slug (for example `subject-line-tester.md`).
3. Follow the template below. Match the shape of the existing entries: an intro paragraph, one fenced artifact block, and a "How to use" list.
4. Add a row to the table in `README.md` under the right category, with the name linked to your file.
5. Open the PR. Keep it to one entry per PR so review stays quick.

### Entry template

```markdown
# Entry Name

**Type:** Prompt &middot; **Access:** Free &middot; **Live page:** (added when it ships on the site)

_One line on what it does._

Two or three sentences on the problem it solves and what the artifact returns.

## The prompt

(or "## The command", "## The memory block", "## The starter list")

​```text
The actual prompt, command, or list. This block is the point: keep it copyable
and complete.
​```

## How to use

1. First step.
2. Second step.
3. Third step.
```

Type values: Prompt, Slash Command, Subagent, MCP Server, Skill. Access values: Free or Paid.

### House rules

- Real, tested artifacts only. No placeholders standing in for the actual prompt.
- No em dashes or en dashes. Use commas, colons, periods, or parentheses.
- Plain, specific language. Skip hype words.
- One clear job per entry.

## Option 2: suggest one on the site

Not set up to open a PR? Suggest an entry at [cc4.marketing/library](https://cc4.marketing/library/) and we will draft it.
